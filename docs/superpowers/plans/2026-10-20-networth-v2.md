# netWorth v2: Next.js rewrite on Vercel

Date: 2026-10-20
Status: Draft, awaiting review
Replaces: the Flask app (`app.py`, `db.py`, `ai.py`, `outlook.py`, `importers.py`) and the VM deploy (`deploy/`).

## Goals

- Host on Vercel (free Hobby plan, personal non-commercial use).
- Set keys once: the OpenAI and Microsoft secrets live in Vercel env vars, and the Outlook login persists through a refresh token stored in Postgres.
- New: draft emails in the app, edit them, then save them to Outlook drafts or send them.
- New: batch AI jobs (for example, "draft a personable email for everyone on my list"). Batch jobs always stop at drafts.
- New: network graph, a customizable mind map of contacts.

## Stack

- Next.js (App Router) and TypeScript. Server Actions for forms. No client state library.
- Vercel Postgres (Neon through the Vercel Marketplace, free tier), with Drizzle for the schema and migrations.
- Auth.js with the Microsoft Entra ID provider. One login gates the app (email allowlist of one) and connects Outlook.
  - Scopes: `Mail.ReadWrite`, `Mail.Send`, `offline_access`.
  - The refresh token is stored in Postgres and auto-renewed.
- `openai` SDK, using the Responses API with `web_search`. Model from `OPENAI_MODEL`.
- `exceljs` for import and export. `d3-hierarchy` for the graph layout, rendered as plain SVG.
- Plain CSS, ported from `static/style.css`.

Env vars: `OPENAI_API_KEY`, `OPENAI_MODEL`, `AUTH_MICROSOFT_ENTRA_ID_ID`, `AUTH_MICROSOFT_ENTRA_ID_SECRET`, `AUTH_MICROSOFT_ENTRA_ID_ISSUER`, `AUTH_SECRET`, `ALLOWED_EMAIL`, `DATABASE_URL`.

## Data model

Port all 7 existing tables (`profile`, `companies`, `contacts`, `email_templates`, `messages`, `applications`, `column_mappings`), keeping the same CHECK constraints and rules. Changes:

- `companies` gains `industry`.
- `contacts` gains `team`, `school`, `program`, `grad_year`, and `attributes jsonb`. The `attributes` column holds user-defined fields such as `{"city": "Toronto"}`.
- `messages` gains `state`: `app_draft` | `outlook_draft` | `sent`.
- New `jobs`: `id`, `instruction`, `template_id`, `status` (`running` | `done` | `cancelled`), `created_at`.
- New `job_items`: `id`, `job_id`, `contact_id`, `status` (`pending` | `done` | `failed`), `error`, `message_id`.
- New `graph_views`: `id`, `name`, `levels` (an ordered array of field keys, for example `["industry", "company", "team"]`).
- New Auth.js tables (`accounts`, `sessions`, `users`) through the Drizzle adapter.

## Phases

### 1. Scaffold
- Create the Next.js app, link it to Vercel, add Neon, write the Drizzle schema, and run the first migration.

### 2. Auth and Outlook connection (do this first: consent spike)
- Set up the Entra provider with the email allowlist. Require login for every route.
- Register `https://<app>.vercel.app/api/auth/callback/microsoft-entra-id` in Azure, and create a client secret.
- Risk: the UWaterloo tenant may block user consent for `Mail.Send` (or for `Mail.ReadWrite`).
  - If `Mail.Send` is blocked, drop it. Drafts still work, and sending happens from Outlook.
  - If everything is blocked, use the mailto fallback, as in v1.

### 3. Port pages
- Port Today, Contacts, Contact, Companies, Find, Applications, Templates, Profile, and Import/Export.
- Keep these rules unchanged: status transitions, follow-up dates, the duplicate rule, `{placeholders}`, and `[[slots]]`.
- The AI "parse profile" step also extracts `team`, `school`, `program`, and `grad_year`.

### 4. Draft editor
- The contact page gets an editor (subject and body) with three actions:
  - **Save**: creates an `app_draft` in the app.
  - **Save to Outlook drafts**: `POST /me/messages`, then `state = outlook_draft`.
  - **Send**: shows a confirm dialog, then sends. A new message uses `POST /me/sendMail`; an existing Outlook draft uses `POST /me/messages/{id}/send`. Then `state = sent`, and the follow-up date is set.
- A Drafts page lists every unsent draft.
  - Bulk "Save to Outlook" for selected drafts.
  - Bulk "Send" shows a confirm dialog with the recipient count.

### 5. Batch AI jobs
- Form inputs: a free-text instruction, an optional template, and contact selection (filter by status, company, or source, plus checkboxes).
- Submitting creates one `jobs` row and one `job_items` row per contact.
- The browser processes the items 3 at a time. Each item is one server call that drafts one contact. That keeps every function call well under the Vercel duration limit.
- Progress is stored in the DB, so a closed tab can resume the job, and failed items can be retried.
- Output is always `app_draft` messages. Jobs never save to Outlook and never send.
- The same job runner can do "enrich": AI fills in missing `industry`, `team`, `school`, `program`, and `grad_year` values so the graph has data.

### 6. Network graph
- The tree is built on request from the contacts. It is never stored.
  - The root is "me". Each level groups contacts by one field. The leaves are contacts.
- Level fields can be any of:
  - built-in: `industry`, `company`, `team`, `title`, `school`, `program`, `grad_year`, `status`, `source`, `how_connected`
  - any key in `attributes`
- Contacts with no value for a level go under an "Unknown" node.
- A level editor lets you add, remove, and drag to reorder levels. A layout can be saved as a named `graph_views` row (for example, "Industry", "School").
- Rendering: `d3-hierarchy` horizontal tree in SVG, with collapsible nodes and pan/zoom.
  - Each node shows a count.
  - Clicking a leaf opens the contact.
  - Clicking a group node opens Contacts filtered to that group.

### 7. Outlook sync
- Port sent and reply detection from `outlook.py`. It runs when the Today page loads, at most once every 10 minutes.

### 8. Tests
- Use Vitest, with OpenAI and Graph replaced by fakes. Port the `test_app.py` coverage, and add:
  - grouping for the graph tree (level order, Unknown bucket, attribute keys)
  - job item processing and resuming
  - message state transitions

### 9. Cutover
- A one-time script copies `networth.db` into Postgres.
- Smoke-test on a preview deploy against real Outlook and OpenAI, then promote to production.
- Delete the Python code and `deploy/`, and shut down the VM.

## Skipped

- Saved contact lists. Filters plus checkboxes cover selection; add lists if the same group gets re-picked often.
- Cron sync. Hobby cron is daily only, and sync on page load covers it.
- Contacts appearing under several values of one level (for example, two schools). Each field holds one value; add multi-value support if it comes up.
- Dragging individual nodes in the graph. Only the levels are rearranged.
