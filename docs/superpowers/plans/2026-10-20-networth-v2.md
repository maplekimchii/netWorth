# netWorth v2: Next.js rewrite on Vercel

Date: 2026-10-20
Status: Done (2026-10-21). Live at https://net-worth-sable-two.vercel.app
Replaces: the Flask app (`app.py`, `db.py`, `ai.py`, `outlook.py`, `importers.py`) and the VM deploy (`deploy/`).

## Goals

- Host on Vercel (free Hobby plan, personal non-commercial use).
- Set keys once: the OpenAI and GitHub secrets live in Vercel env vars.
- New: draft emails in the app, edit them, then open them in Outlook on the web to send.
- New: batch AI jobs (for example, "draft a personable email for everyone on my list"). Batch jobs always stop at drafts.
- New: network graph, a customizable mind map of contacts.

## Stack

- Next.js (App Router) and TypeScript. Server Actions for forms. No client state library.
- Vercel Postgres (Neon through the Vercel Marketplace, free tier), with Drizzle for the schema and migrations.
- Auth.js with the GitHub provider. Login is gated to one GitHub account (`ALLOWED_GITHUB_LOGIN`).
- No Outlook API. On 2026-10-21 the UWaterloo tenant required admin approval for any third-party app, even with `Mail.ReadWrite` alone (approval was requested; not granted). Emails open in Outlook on the web through the compose deeplink `https://outlook.office.com/mail/deeplink/compose?to=…&subject=…&body=…`, and sent/replied are marked by hand, like v1's fallback mode.
- `openai` SDK, using the Responses API with `web_search`. Model from `OPENAI_MODEL`.
- `exceljs` for import and export. `d3-hierarchy` for the graph layout, rendered as plain SVG.
- Plain CSS, ported from `static/style.css`.

Env vars: `OPENAI_API_KEY`, `OPENAI_MODEL`, `AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET`, `AUTH_SECRET`, `ALLOWED_GITHUB_LOGIN`, `DATABASE_URL`.

## Data model

Port all 7 existing tables (`profile`, `companies`, `contacts`, `email_templates`, `messages`, `applications`, `column_mappings`), keeping the same CHECK constraints and rules. Changes:

- `companies` gains `industry`.
- `contacts` gains `team`, `school`, `program`, `grad_year`, and `attributes jsonb`. The `attributes` column holds user-defined fields such as `{"city": "Toronto"}`.
- `messages` drops `outlook_message_id` and `outlook_conversation_id`. A message is a draft until `sent_at` is set (no separate state column).
- New `jobs`: `id`, `kind` (`draft` | `enrich`), `instruction`, `template_id` (null: AI writes the whole email), `status` (`running` | `done` | `cancelled`), `created_at`.
- New `job_items`: `id`, `job_id`, `contact_id`, `status` (`pending` | `done` | `failed`), `error`, `message_id`.
- New `graph_views`: `id`, `name`, `levels` (an ordered array of field keys, for example `["industry", "company", "team"]`).
- New Auth.js tables (`accounts`, `sessions`, `users`) through the Drizzle adapter.

## Phases

### 1. Scaffold
- Create the Next.js app, link it to Vercel, add Neon, write the Drizzle schema, and run the first migration.

### 2. Auth
- GitHub provider with the one-account allowlist. Require login for every route.
- GitHub OAuth app callback: `https://<app>.vercel.app/api/auth/callback/github`.
- Outlook consent spike: done, blocked (see Stack).

### 3. Port pages
- Port Today, Contacts, Contact, Companies, Find, Applications, Templates, Profile, and Import/Export.
- Keep these rules unchanged: status transitions, follow-up dates, the duplicate rule, `{placeholders}`, and `[[slots]]`.
- The AI "parse profile" step also extracts `team`, `school`, `program`, and `grad_year`.

### 4. Draft editor
- The contact page gets an editor (subject and body) with three actions:
  - **Save**: saves the `draft` in the app.
  - **Open in Outlook**: opens the compose deeplink in a new tab, prefilled with recipient, subject, and body.
  - **Mark sent**: `state = sent`, and the follow-up date is set. **Mark replied** works as in v1.
- A Drafts page lists every unsent draft, each with Open in Outlook and Mark sent.
- Long bodies: keep the deeplink URL under about 2,000 characters; past that, copy the body to the clipboard and open compose with subject only.

### 5. Batch AI jobs
- Form inputs: a free-text instruction, an optional template, and contact selection (filter by status, company, or source, plus checkboxes).
- Submitting creates one `jobs` row and one `job_items` row per contact.
- The browser processes the items 3 at a time. Each item is one server call that drafts one contact. That keeps every function call well under the Vercel duration limit.
- Progress is stored in the DB, so a closed tab can resume the job, and failed items can be retried.
- Output is always `draft` messages. Jobs never send.
- The same job runner can do "enrich": AI fills in missing `industry`, `team`, `school`, `program`, and `grad_year` values from what is already known (title, notes, company); no web search. It never overwrites a filled field.
- A contact who already has an unsent draft is skipped (item fails with a reason), which also keeps a re-run from duplicating drafts.

### 6. Network graph
- The tree is built on request from the contacts. It is never stored.
  - The root is "me". Each level groups contacts by one field. The leaves are contacts.
- Level fields can be any of:
  - built-in: `industry`, `company`, `team`, `title`, `school`, `program`, `grad_year`, `status`, `source`, `how_connected`
  - any key in `attributes`
- Contacts with no value for a level go under an "Unknown" node.
- A level editor lets you add, remove, and drag to reorder levels. A layout can be saved as a named `graph_views` row (for example, "Industry", "School").
- Rendering: `d3-hierarchy` horizontal tree in SVG, with collapsible nodes and pan/zoom.
  - Each node shows a count.
  - Clicking a leaf opens the contact.
  - Clicking a group node folds or unfolds it (mind-map style). Zoom with buttons; drag to pan.
- Custom fields: contacts' edit form has a `key: value` box stored in `attributes`; each key becomes an available level.
